# تشغيل سيرفر التراخيص

سيرفر واحد مركزي تديره أنت، يخدم كل العملاء. يتكون من الخدمة وقاعدة Postgres و Caddy للشهادة.

## 1. المفاتيح (مرة واحدة فقط)

```bash
pnpm --filter @inv/license-server generate-keys
```

الأمر يطبع مفتاحين:

- `LICENSE_PRIVATE_KEY` و `SERIAL_HMAC_KEY` و `BETTER_AUTH_SECRET`: تذهب إلى ملف `.env` على السيرفر.
- `MAIN_VITE_LICENSE_PUBLIC_KEY`: يدخل في بناء البرنامج.

احتفظ بنسخة مشفرة من المفتاح الخاص خارج السيرفر. لو ضاع، كل عميل سيحتاج نسخة جديدة من البرنامج. ولو تسرب، أي شخص يستطيع إصدار تراخيص، فولّد مفاتيح جديدة وأعد بناء البرنامج.

`SERIAL_HMAC_KEY` إذا تغير تتوقف كل السيريالات التي لم تُفعّل بعد.

## 2. التشغيل على VPS

```bash
cd deploy/license-server
cp .env.example .env
```

عدّل `.env`، ووجّه الدومين إلى السيرفر، ثم:

```bash
docker compose up -d --build
```

Caddy يطلب الشهادة تلقائياً. تأكد من فتح المنفذين 80 و 443.

## 3. أول حساب أدمن

لا يوجد تسجيل عام، فالحساب يُنشأ من السيرفر فقط:

```bash
docker compose exec server node dist/create-admin.mjs
```

عند أول دخول تفتح اللوحة شاشة تفعيل التحقق بخطوتين، ولا يفتح شيء قبلها. احفظ رموز الطوارئ.

## 4. بناء البرنامج للعملاء

```bash
MAIN_VITE_LICENSE_PUBLIC_KEY='...' MAIN_VITE_UPDATE_PUBLIC_KEY='...' MAIN_VITE_LICENSE_SERVER_URL='https://licenses.example.com' pnpm dist
```

الأمر يرفض البناء بدون المفتاحين العامين والعنوان. البرنامج المبني لا يقبل مفتاح التطوير.

## التحديثات

مفتاح التحديث منفصل عن مفتاح التراخيص، ولا يوضع على السيرفر أبداً.

```bash
pnpm --filter @inv/license-server generate-update-key
```

احفظ المفتاح الخاص خارج المستودع مع نسخة أوفلاين، وأضف `MAIN_VITE_UPDATE_PUBLIC_KEY` لمتغيرات البناء. `pnpm dist` يرفض البناء بدونه.

لنشر إصدار جديد: غيّر `version` في `apps/desktop/package.json` وابنِ، ثم:

```bash
UPDATE_SIGNING_KEY_FILE=/path/to/update.pem pnpm --filter @inv/desktop publish-update
```

ارفع ملف الـ exe أولاً ثم `manifest.json` إلى `deploy/license-server/updates/` على السيرفر. بهذا الترتيب لا يوجد وقت يشير فيه البيان إلى ملف غير موجود. لا حاجة لإعادة تشغيل السيرفر.

البرامج المثبتة تفحص عند التشغيل وكل 6 ساعات، وتثبت التحديث عند الإغلاق.

## الذكاء الاصطناعي

متوقف افتراضياً. لتشغيله أضف إلى `.env` على السيرفر:

```bash
AI_ENABLED=true
GEMINI_API_KEY=...
AI_DAILY_BUDGET_USD=10
```

المفتاح لازم يكون من مشروع Google Cloud بفوترة مفعلة. الباقة المجانية ممنوعة لبيانات العملاء، لأن Google قد تستخدمها ويراجعها بشر. وضيف تنبيه ميزانية في Google Cloud.

لكل ترخيص: صفحة الترخيص ← الذكاء الاصطناعي ← تفعيل مع حد شهري. التغيير يوصل للجهاز عند اتصاله القادم. والاستهلاك والتكلفة في صفحة استهلاك الذكاء الاصطناعي.

للإيقاف الكامل: `AI_ENABLED=false` ثم أعد تشغيل الخدمة.

## 5. النسخ الاحتياطي

```bash
docker compose exec postgres pg_dump -U licenses licenses > licenses.sql
```

جدوله يومياً وانقل الملف خارج السيرفر. ضياع هذه القاعدة لا يوقف البرامج العاملة، لأن التحقق يتم أوفلاين، لكنك تفقد سجل العملاء والمدفوعات ولا تستطيع التمديد.

## 6. العمل اليومي

| المطلوب | من أين |
|---|---|
| عميل جديد | العملاء ← إضافة عميل ← إصدار سيريال |
| تجديد | صفحة الترخيص ← تمديد، ثم يفتح العميل صفحة الترخيص ويضغط تحديث، أو ينتظر الاتصال التلقائي كل ساعة |
| عميل بدون إنترنت | صفحة الترخيص ← كود تفعيل أوفلاين، برقم الجهاز من شاشة العميل |
| جهاز جديد للعميل | فك الربط بالجهاز، ثم يفعّل نفس السيريال |
| سيريال ضاع | سيريال بديل |
| لم يدفع | إيقاف. يصبح البرنامج قراءة فقط عند اتصاله القادم، والبيانات تبقى متاحة له |

الإيقاف يصل عند اتصال البرنامج بالإنترنت فقط. جهاز لا يتصل أبداً يظل يعمل حتى نهاية مدته.
